# Convenções do front v2

Regras curtas pra toda tela nova seguir o mesmo padrão. Se uma regra daqui atrapalhar, muda a regra aqui — não abre exceção na tela.

## Estilo global

- **Tokens** (`src/estilo/tokens.css`): cor, fonte, tamanho de letra (`--v2-fs-*`), raio (`--v2-r-*`), sombra. Moram no `:root`; o tema é `data-tema="claro|escuro"` no `<html>` (aplicado no `index.html` antes do 1º desenho; a escolha fica em **Configurações → Aparência** via `useTema`, estado compartilhado em `layout/useTema.ts`).
- **Base global** (`src/estilo/global.css`): box-sizing, fundo/cor/fonte da página, seleção de texto, foco de teclado, **barra de rolagem** e `prefers-reduced-motion`. Visual que vale pro app inteiro mora aqui — nunca remendado dentro de um componente.
- Os dois CSS globais são importados **antes** de qualquer componente no `main.tsx` (o CSS de componente vem depois e ganha no empate).
- Tela usa CSS Module ao lado do `.tsx`, sempre com `var(--v2-*)`. Nada de cor ou tamanho de letra cru.

## Componentes (`src/componentes/`)

Peça que aparece em mais de uma tela vira componente aqui. A tela escolhe **variante e tamanho**; medida e cor ficam no componente. `className` nos componentes é só pra posição/largura no layout da tela.

| Precisa de… | Use | Notas |
|---|---|---|
| Botão | `Botao` | `variante` primario / secundario (padrão) / texto · `perigo` · `tamanho` md 36 / lg 44 · `soIcone` · `ativo` · `cheio` · `compactoNoCelular` · `icone` |
| Campo de formulário | `Campo` | rótulo + controle + erro. `erro` deixa o controle vermelho e liga a mensagem (aria). `grupo` pra 2 controles ("de … até"), `estatico` + `ValorFixo` pra valor que não muda |
| Caixa de texto | `Entrada` | md 44 / sm 40 · `prefixo` ("R$") · `sufixo` (ex.: olho da senha). Dentro do `Campo` herda id e erro sozinha |
| Escolha numa lista | `Selecao` | no lugar de `<select>`. md 44 / sm 40 / xs 32. Dentro do `Campo` herda id e erro. Opção com `detalhe` mostra um complemento apagado ao lado ("A · 0,30"). A lista aberta é `position: fixed` (não corta nem rola o pai) |
| Data | `SeletorData` | no lugar de `<input type="date">` (calendário próprio, tema, teclado). `min`/`max`, `limpavel` pra data opcional. Valor sempre `YYYY-MM-DD` |
| Menu de seções (página grande) | `NavSecoes` | ícone + nome, ativa como o item do menu principal, link `?s=<id>`; faixa rolável no celular |
| Valor em dinheiro (campo principal) | `EntradaValor` | R$ grande, dígitos viram centavos, nunca negativo, até 12 dígitos · `compacto` = caixa comum com "R$" na frente, pra dinheiro secundário que divide a linha (saldo inicial, limite) |
| Valor em dinheiro (filtro/campo pequeno) | `Entrada` + `prefixo="R$"` + `maskMoney` | nunca `type="number"` (aceita sinal de menos) |
| Escolha única curta (2–4 opções) | `Segmentos` | radiogroup com setas; `cheio` pra ocupar a largura |
| Liga/desliga | `Interruptor` | role=switch ("Já paguei") |
| Marcar (caixa) | `Marcar` | checkbox de verdade com a cor do tema; `misto` pro "marcar todos" com parte marcada (Importar extrato). Nada de `<input type="checkbox">` cru em tela nova |
| Status | `Etiqueta` | tom positivo / negativo / alerta |
| Layout de formulário | `Formulario`, `LinhaCampos`, `RodapeFormulario` | `layout="pilha"` empilha; `layout="lateral"` = `<Campos>` à esquerda + `<Lado>` (prévia, opções, rodapé) à direita, 1 coluna no celular. `LinhaCampos colunas="2fr 1fr"` pra proporção sob medida |
| Prévia do lançamento | `PreviaLancamento` | "Como vai aparecer": linha igual à da lista + frase do efeito; some no celular |
| Lista de lançamentos por dia | `ListaPorDia` | Transações, fatura do cartão… — cabeçalho do dia, linha com inicial/ícone, nome, detalhe, hora, etiqueta, valor. Mantém a ordem recebida |
| Barra de proporção | `BarraProgresso` | limite usado, fatura paga, parcelas pagas (4px, tom alerta/negativo/positivo) |
| Carinha do cartão | `FaceCartao` | cartão em miniatura (proporção 1,6:1) na cor do banco: chip, bandeira no canto, últimos dígitos no `lg` (md 72×45 na lista, lg 112×70 no cabeçalho) |
| Busca de lista | `Busca` | lupa + input de pesquisa, 36px, à esquerda da barra da lista (Transações, Cartões); quem filtra é a tela |
| Casca de tela de formulário | `PaginaFormulario` | título + aviso de carga/esqueleto + o formulário (Nova transação, Novo/Editar cartão) |
| Ações de uma linha | `Menu` | ⋮ com itens (ícone, perigo); fecha fora/Esc/ao escolher. Pra ação que não merece botão na linha |
| Paginação de lista | `Paginacao` | linhas por página + páginas numeradas; servidor pagina |
| Confirmar ação | `Confirmar` | excluir/estornar; `perigo` pra destrutiva |
| Caixa de conteúdo | `Bloco` | título + ação à direita |
| Valor em dinheiro | `Dinheiro` | respeita "esconder valores" |

## Formulário

- Todo campo dentro de `Campo` (nunca `<label>` solto com `<input>` estilizado na tela).
- Valida ao enviar, mostra erro **no campo** (vermelho, embaixo), limpa o erro ao editar, não chama o servidor se estiver inválido. Erro do servidor vai num aviso no topo do formulário. O erro do campo **não ocupa altura** (desenha no respiro de 18px entre campos — aparecer/sumir não mexe na tela), então é **uma linha curta** (corta com reticências; texto inteiro no title).
- Limite de caracteres igual ao do back (ex.: descrição 255).
- Hover de linha de lista usa `--v2-hover-linha` (cor do fundo da página), nunca `--v2-superficie-2`: essa é a cor da bolinha, da etiqueta e do trilho que ficam DENTRO da linha e sumiam ao passar o mouse (2026-10-15).
- Busca com espera de digitação: `utils/useAtrasado.ts` (Transações, lançamentos da fatura) — nunca bater no servidor a cada tecla.
- **Ordem de Transações** (2026-10-19): sem período escolhido, a lista vai até HOJE com o mais recente em cima (as previsões das contas fixas, geradas meses pra frente, empurravam hoje pro fim). Filtro de status "Previsto" mostra os próximos do mais perto pro mais longe (`data_asc`); período escolhido vale como pedido.
- Conta bancária: tipos, validação (agência/número) e a linha de detalhe em `src/dominio/conta.ts`. Conta **encerrada** sai das seleções (`getContas()` já filtra; a tela de contas pede `incluirEncerradas`).
- Tipos de conta e grupos da lista (em conta / poupança / investimentos / dinheiro por último) vêm de `src/dominio/conta.ts` (`TIPOS_CONTA`, `ehGuardado`, `ehDinheiro`, `temDadosBancarios`): Dinheiro não tem banco/agência/número (o formulário esconde); "Guardado" = poupança + investimentos; a carteira é sempre dinheiro, mesmo com tipo antigo.
- **Bancos é só das contas** (decisão 2026-10-15, modelo Pierre): a linha abre, ali embaixo, a ficha (banco, tipo, agência, número) e as ações — sem página de detalhe nem extrato ali. Extrato é Transações: quem quer abrir Transações já filtrada manda `state.filtros` (ex.: `{ contaId }`, usado pelo "Ver em Transações" de Importar extrato). Outra tela devolve a pessoa pra lista com a conta aberta por `state.abrir` (Nova/Editar/Encerrar fazem isso).
- **Lista com ficha na linha = `componentes/ListaFicha`** (`ListaFicha`, `GrupoFicha`, `ItemFicha`, `DadosFicha`, `AcoesFicha`, `InicialFicha`): Bancos e Categorias usam. Cadastro novo com esse jeito passa só o conteúdo; nunca redesenhar a linha/ficha por tela.
- **Categorias** (2026-10-16): Despesas | Receitas ("as duas" aparece nas duas), as da pessoa primeiro e depois as padrão; a ficha tem as subcategorias (as da pessoa com Editar/Excluir) e "Nova subcategoria"; padrão não muda nem sai. Excluir em uso vai pra `/categorias/:id/excluir` (ou `/subcategorias/:id/excluir`) e pergunta pra onde vai o que está nela; quem diz se precisa é o servidor (`precisaDestino`, conta até lançamento excluído).
- **Importar extrato** (`/importar`, 2026-10-16): conta + arquivo (OFX ou CSV) → se o CSV não for reconhecido, "Não reconhecemos as colunas" do jeito do YNAB/Actual (pesquisa 2026-10-17): a prévia do arquivo em cima (coluna escolhida ganha etiqueta) e um campo por informação embaixo (Data, Descrição, Dinheiro que entrou, Dinheiro que saiu; cada opção é uma coluna com um exemplo). Uma coluna só de valor = a mesma em entrou e saiu (escolher uma preenche a outra); sem "valor com sinal" nem "não usar" → prévia com cada linha marcada (o que já está no app vem desmarcado) e a categoria sugerida → resumo. A chave de idempotência nasce com cada prévia. Planilha de banco não tem padrão: a tela pergunta, o código não adivinha banco por banco. Arquivos pra testar: `docs/features/importacao/exemplos/`.
- **Reconciliação** (`/reconciliacao`, 2026-10-18): uma conta por vez (lembrada no navegador; sem isso, a 1ª com saldo que não é a carteira). Topo: saldo no app + última conferência ("Bate" só se nada se moveu desde ela). "Conferir saldo": dia + saldo no banco → o app mostra o que tem até ali e a diferença ao vivo; salvar grava o marco (verificação, com chave de idempotência por tentativa). Lista de conferências com a ficha na linha: diferença recalculada AGORA (a pessoa pode ter lançado o que faltava), Ajustar (lançamento de ajuste), Lançar o que falta, Agora bate: confirmar, Ver lançamentos (Transações filtrada pelo período entre marcos), Remover (confirma). O saldo inicial aparece como "Ponto de partida" (edita na conta). Sem calendário nem tabela de movimentos (o app antigo tinha; aqui é lista, modelo das outras telas).
- **Espaços** (2026-10-18, decisão do Gustavo; modelo Notion/Slack): o **menu da conta** (bloco da pessoa embaixo do menu lateral, modelo Notion; sai da barra por cima do conteúdo, 320px) tem três partes: a conta ativa (clicar nela = espaço **Pessoal**; nada de item "Pessoal" na lista) com as **Famílias** dela (estado em `estado/espaco.ts`, recarrega ao trocar de conta), **Contas** (as outras conectadas neste navegador: clicar troca via `POST /auth/switch`; "Adicionar conta" abre `/entrar?adicionar`, que usa `POST /auth/add-account` sem sair da atual; conta com MFA não entra por aí, a API devolve 409) e as ações (Configurações, Convites pra você, Sair = todas). A lista de contas mora no navegador (`v2:contas`, `AuthProvider`: `contas`, `adicionarConta`, `trocarConta`); login frio zera a lista; o conteúdo é remontado com o id da conta na chave, então nada fica com dado da conta anterior. O bloco diz em qual espaço a pessoa está; a URL diz o espaço (`/familias/:id/...` = aquela família, `familiaDaRota`) e o `V2Layout` troca o menu inteiro: família = Visão geral (`/familias/:id`), Despesas compartilhadas (`/despesas`), Entre vocês (`/entre-voces`) · Gerenciar: Membros (`/membros`), Dependentes (`/dependentes`), Regras (`/regras`). Convites pra pessoa e "Nova família" ficam nesse menu (`/familias` e `/familias/nova` não são espaço; "Famílias" saiu do menu). O mês das páginas da família é um só (`usePeriodoFamilia`). Tela interna (convidar, novo acerto, dependente) volta pra página do menu a que pertence (`raiz` em `secaoDaRota`). Peças comuns em `telas/FamiliaPecas.tsx`; cada página tem o seu arquivo `telas/Familia*.tsx`. Páginas não repetem o título do topo num Bloco: a ação ("Convidar", "Adicionar", "Ver todas") vai no `extra` do `GrupoFicha`.
- **Metas** (2026-10-19, modelo de CAIXINHA do Nubank, decisão do Gustavo): cada meta tem a própria caixinha (conta tipo 7) e guardar TIRA o dinheiro da conta e põe nela (transferência; resgatar devolve). `/metas`: faixa (guardado nas metas, falta, por mês pra chegar no prazo) + barra da lista no padrão de Bancos (`Segmentos` Em andamento | Concluídas à esquerda, Botao "Nova meta" com + à direita; ação de criar SEMPRE nessa barra) e a grade de cartões estilo caixinha (ícone, situação, nome, guardado, "de R$ y", barra, "Até mês/ano" e por mês) que abrem `/metas/:id` (`MetaPagina`: cabeçalho com ícone, "Guardado" grande com Resgatar e Guardar, Histórico por dia em `ListaPorDia` (Guardou de X / Resgatou pra Y), coluna Plano com Excluir/Editar; excluir com dinheiro pede pra resgatar antes; "Chegou lá" (situação `chegou-la`, continua Em andamento) ganha "Concluir e usar o dinheiro" (`/metas/:id/concluir`, o terceiro modo de `MovimentoMeta`: conta + valor fixo = o guardado todo); só a marcada vai pra Concluídas e é REGISTRO: "Juntou", plano e histórico, sem Guardar/Resgatar/Editar/Excluir, e um botão só, "Criar outra igual" (`/metas/nova` com `state.modelo`: nome, ícone, quanto e a mesma duração do prazo a partir deste mês, zerada)). Instante do servidor (`criadoEm`, `entrouEm`…) vira dia com `diaDeInstante`; `dataBR` é só pra data sem hora. `/metas/nova` e `/metas/:id/editar` (`MetaFormulario`: sugestões que preenchem nome+ícone, nome, quanto, ícone em radiogroup, prazo mês+ano). `/metas/:id/guardar` e `/metas/:id/resgatar` (`MovimentoMeta`: conta com o saldo no detalhe, teto = saldo da conta ou guardado, "Guardar tudo"/"Resgatar tudo", data local, Idempotency-Key gerada ao abrir). Ícones, temas e rótulos em `dominio/meta.ts`. Caixinha nunca aparece em seleção de conta (`getContas()` esconde); Bancos mostra o grupo "Caixinhas das metas" só pra ver (ficha com "Abrir a meta"); Início junta as caixinhas numa linha. Metas da família ficam pro espaço da família (a lista pede `?pessoais=true`).
- **Respostas** (2026-10-19, docs/features/respostas/visao.md): a frase que responde vem pronta do servidor e aparece em `componentes/Resposta` (tom + texto + ações que navegam; "R$" não quebra do número). O que ainda vem no mês = `componentes/ListaAindaVem` (nome · dia · categoria, valor, % da renda opcional, link pra conta fixa). A renda do mês e o que come ela = `componentes/UsoDaRenda` (barra empilhada com séries `--v2-serie-1..5` e cinzas, o que vem listrado, marca "sua renda", legenda já saiu · ainda vem · livre/passou, resposta); mora no Início e vai pra Renda e Relatórios. `BarraProgresso` tem `fracaoAVir` (listrado). Formulário de meta pergunta "cabe?" enquanto a pessoa preenche (`useAtrasado`) e oferece "Usar <mês> como prazo".
- **Limites** (2026-10-19, vale todo mês até mudar): `/limites` = `NavegadorMes` ("Limites de …") + faixa (limite do mês, gasto, sobra/passou) + lista com "Novo limite" na barra; grupo "Com limite" (quem passou e quem está perto primeiro; linha: gasto de limite, "mais R$ x previsto", etiqueta Passou/Perto do limite, sobra ou "R$ x a mais", barra; ficha com Limite por mês, Gasto, Ainda vai cair, Sobra/Passou, Vale desde, Tirar limite/Editar) e grupo "Sem limite" (quem gastou sem limite, ficha com "Pôr limite"). Mês passado só mostra (sem botões). `/limites/novo?ano&mes[&categoria]` e `/limites/editar?ano&mes&categoria` (`LimiteFormulario`: categoria de gasto sem limite no mês, limite por mês, "Vale a partir de" fixo, média dos 3 meses antes com "Usar a média"); volta pra lista no mesmo mês com a linha aberta.
- **Foto de perfil** (2026-10-18): `componentes/Avatar` (foto ou iniciais, volta pras iniciais se a imagem não carregar) + `urlFoto(id, fotoEm)`; `InicialFicha` aceita `foto`. A própria foto vem do `usuario.fotoEm`; a dos outros vem do membro da família (`fotosDe(detalhe)` em `FamiliaPecas`: usuarioId → URL) e entra em quem pagou, no equilíbrio e nas passagens. Configurações → Perfil no modelo do Instagram: foto grande clicável (passar o mouse mostra a câmera) com nome e e-mail ao lado e "Editar perfil" no canto; clicar na foto abre `Dialogo` "Foto do perfil" com a foto grande e as opções empilhadas (Carregar/Trocar, Remover, Cancelar). JPG/PNG/WebP até 8 MB, checado antes de enviar. `componentes/Dialogo` = janela genérica (ver, escolher); confirmação de ação continua sendo o `Confirmar`. Conta conectada que não é da família fica com as iniciais (o servidor não mostra foto pra quem não divide família).
- **Formulário dentro de caixa preenche a caixa** (Gustavo, 2026-10-18: "sobrando muito espaço vazio" no Perfil e em Trocar senha): nada de `max-width: 420px` deixando metade do `Bloco` vazia. Campos curtos lado a lado com `LinhaCampos` (2 ou 3 colunas); linha de rodapé com a caixa de marcar à esquerda e os botões à direita; passo de um campo só (senha, código) leva o campo (até 420px) e os botões na mesma linha. Olhar a caixa cheia antes de mostrar.
- **Famílias** (`/familias`, 2026-10-18): lista com os convites pra pessoa (aceita/recusa ali) e cada família como linha que abre o resumo do mês. Conteúdo das páginas da família (pesquisa: Splitwise/Tricount/Settle Up separam despesas de saldos, Honeydue tem visibilidade por pessoa): **Visão geral** = `NavegadorMes` + UM bloco que conta o mês (despesas da família; "Renda da casa" só se alguém além de você liberou o valor pra você, listando só quem mostra; quem pagou · a parte → "pagou a mais" / "pagou a menos" / "Equilibrado", como FATO; nunca "deve", "a receber", "a acertar"; "Pra equilibrar o mês: X → Y R$ V" com "Marcar como feito" ou "Mês equilibrado"; "Passou entre vocês" com o botão "Dinheiro entre vocês") e, embaixo, só o que pede ação (grupo "Aguardando aprovação" com "Ver todas"); **Despesas compartilhadas** = grupo "Aguardando aprovação" primeiro e o mês (etiqueta só Aguardando/Recusada; aprovação, Recusar e responsável na própria linha; sem filtro); **Entre vocês** = quem pagou o quê + "Pra equilibrar" + "Passou entre vocês" com "Dinheiro entre vocês"; **Membros** = membros (na SUA ficha: relação, renda do mês com "Ver renda" e **"Quem vê a sua renda"** = uma caixa por membro que lança; na dos outros a renda só aparece se a pessoa liberou pra você, senão nem linha), convites; **Dependentes** (idade e gasto do mês); **Regras** = Selecao de divisão, Interruptor "Pedir OK pra despesa grande" + "a partir de", e Sair/Dissolver só como botão (a consequência vai no Confirmar). Sem cabeçalho na página (o bloco da conta já diz a família); sem contador nem chip. Formulários são páginas: nova família, convidar (e-mail + relação + "lança e divide" | "só ver"), dependente, registrar acerto (vem preenchido pelo balanço). Rótulos e listas em `src/dominio/familia.ts`. Quem só vê (permissão Dependente) não ganha botão de ação, não vê renda de ninguém e fica fora da divisão (o servidor manda).
- **Renda** (2026-10-18, `docs/features/familia/renda-e-visibilidade.md`): renda é da PESSOA. Página **Renda** no menu principal (`/renda`, `telas/Renda.tsx`; não é configuração): esperado = fixa + variável que a pessoa DECLARA (conta fixa é conta a pagar, nunca renda; sem linha no mês vale a do último mês) × recebido (o que caiu em "Renda"; "Dinheiro que volta" fica fora) e as entradas do mês. Visão geral tem o cartão "Renda do mês". O que a família vê se escolhe NA família (ficha do próprio membro), não aqui. `GET /familias/:id/renda` já vem filtrada por quem pede; nunca valor no membro pro front esconder. Tipos em `types/Renda.ts`, serviço `rendaService.ts`.
- Conta fixa: repetição, regra por extenso e situação em `src/dominio/contaFixa.ts`; criar e editar a regra é o `FormularioContaFixa` (formulário próprio: sem hora/parcela, com subcategoria opcional e **Como paga** obrigatório). O formulário da transação não tem nada de conta fixa (nem interruptor nem atalho: Gustavo tirou). Formas de pagamento: `MEIOS_PAGAMENTO` (transação), `MEIOS_RECEBIMENTO` (receita), `MEIOS_CONTA_FIXA` / `MEIOS_RECEBIMENTO_FIXO` em `src/dominio/transacao.ts`.
- Ciclos de fatura (meses contínuos, vazio quando não há fatura, estado da fatura) moram em `src/dominio/fatura.ts` e espelham o servidor.
- Listas e regras de domínio usadas por mais de uma tela (meios de pagamento, parcelas, frequências, limites) moram em `src/dominio/`, não copiadas por tela.
- Topo: olho (esconder valores) · sino (não lidas, `estado/notificacoes.ts`, consulta a cada minuto e a cada troca de tela) · "Nova transação". Menu lateral: só as seções; **Configurações e Sair ficam no menu da conta** (o bloco avatar + nome no pé é um botão, em todo estado do menu — aberto, trilho e gaveta). Tela sem item no menu (Notificações) é `semMenu` em `secaoDaRota`: ganha a seta de voltar pra onde a pessoa estava.
- Telas de autenticação (Entrar, Cadastro, Redefinir senha) dividem `telas/Auth.module.css` (palco + painel). Regra de senha em `src/dominio/senha.ts` (espelha o servidor: 15–128, sem composição; senhas comuns só no servidor). Cadastro: aceite da Política de Privacidade **nunca** pré-marcado (LGPD); no beta não loga — mostra a mensagem da API (conta aguardando aprovação). Redefinir senha (`/redefinir-senha?token=`) é a tela do link do e-mail; sem token ou com token vencido, manda pro Entrar já no passo "esqueci" (`state.esqueci`). Termos e Privacidade são telas públicas do v2 (`telas/Legal.tsx`), e os links do Entrar/Cadastro apontam pra elas.
- Configurações separadas por assunto, como a Conta do Google (2026-10-15): `NavSecoes` à esquerda (`?s=`, vira faixa rolável no celular) e o conteúdo da seção à direita, blocos um embaixo do outro. **Segurança e login**: `TrocarSenha` ("Sair dos outros aparelhos" marcado), `SegurancaMfa` (QR + chave, códigos de recuperação UMA vez, desativar pede senha + código), `SegurancaDispositivos` (sessões ativas + dispositivos confiáveis; ação em massa pede confirmação). Perfil · Aparência · Dados e privacidade. Datas de sessão/dispositivo vêm em UTC sem fuso → `dominio/dispositivo.ts` (`quandoLocal`). O campo de código do login aceita código de recuperação (tem letra: sem teclado só numérico).
- Convite de MFA pós-login (`telas/ProtejaConta.tsx`, `/proteja-sua-conta`): o Entrar pergunta `mfa/status.mostrarConvite` depois de entrar e passa por ele antes da Visão geral. Só convida (MFA é opt-in): "Ativar agora" abre o `SegurancaMfa` ali mesmo (`iniciar`/`aoConcluir`/`aoCancelar`); "Agora não" adia 30 dias; "Não perguntar mais" dispensa de vez — resposta no servidor (`Usuario.MfaConviteAdiadoAte`/`MfaConviteDispensado`), vale em todo dispositivo; falha de rede nunca prende a pessoa.
- Estado compartilhado entre telas (olho, contador do sino, tema) mora em `src/estado/` (ou `layout/useTema.ts`) com `useSyncExternalStore` — nunca prop drilling nem contexto só pra isso.
- "Voltar" é a seta no **topo**, antes do título da seção (o layout põe sozinho em toda rota abaixo da raiz da seção) — a página não repete o nome da seção nem desenha link de voltar.
- Ações da página (salvar, editar, excluir, estornar) ficam **no pé, à direita**, no `RodapeFormulario` — nunca no cabeçalho. Destrutiva à esquerda, principal à direita.
- Página de formulário/detalhe **não** tem `max-width`: o conteúdo termina na mesma linha dos botões do topo (fresta à direita parece erro de alinhamento).
- Formulário de dinheiro = layout lateral com `PreviaLancamento` à direita. Criar e editar usam **o mesmo** componente (`telas/FormularioTransacao.tsx`, com ou sem `transacao`; `telas/FormularioContaFixa.tsx`, com ou sem `recorrente`) — nunca dois formulários parecidos que divergem.
- Filtro de período: o back trata `to` como exclusivo (`Data < to`) — mande `diaSeguinte(ate)` pra o "até" incluir o dia.
